# WarehouseZero — Project Context

**Hermes: when working in this repo, follow these rules.**

## Architecture

Single-page React 19 + Vite + Tailwind app backed by Firebase (Auth + Firestore + Cloud Functions). Entry point: `src/App.jsx` — state-based SPA routing (no React Router).

**Firestore collections:**
- `users` — Admin, Staff Pusat, Staff Cabang
- `branches` — DISTRIBUTOR / RESELLER cabang & gudang
- `brands` — master merk (auto-registered during spreadsheet import)
- `products` — SKU, kategori, brand, tier pricing (selling/reseller/distributor)
- `product_pricings` — tier pricing log
- `inventory` — approved stock (global + per-branch)
- `stock_movements` — audit log (has Purge feature)
- `stock_transfers` — antar-cabang (Transit/Pending/Received)
- `stock_bundles` — recipe-based packages (components + qty)

**Key services:** `dataService.js` (Firestore CRUD heart — ~2300 lines), `authService.js`, `cloudFunctionsService.js`, `spreadsheetService.js` (SheetJS XLSX parsing).

**Key components (flagged as large in CODEBASE_MAP.md):**
- `ProductManagement.jsx` (~2400 lines) — master produk, SKU, variasi, spreadsheet import, pricing tier, **Paket Bundling** sub-tab
- `StockOut.jsx` (~2200 lines) — Barang Keluar: Retail, **dual-mode Bundling** (Preset vs Custom with editable price for negotiation), Mutasi Pusat→Cabang
- `StockIn.jsx` (~900 lines) — Restock, Produksi, terima mutasi
- `BranchMonitoring.jsx` (~800 lines) — Dashboard Pusat monitoring cabang + Purge
- `UserManagement.jsx` (~600 lines) — admin staff CRUD

## Coding Style (Ponytail Rules)

See `.agents/rules/ponytail.md` and `.agents/rules/token-efficiency.md`.

- Lazy = efficient, not careless. Climb the YAGNI ladder before writing any code.
- No abstractions not explicitly requested. No new deps if avoidable.
- Deletion over addition. Boring over clever. Fewest files possible.
- Bug fix = root cause, not symptom. Grep every caller of the function you touch.
- Mark deliberate simplifications with `ponytail:` comment naming the ceiling.
- **Token efficiency:** ALWAYS read `docs/CODEBASE_MAP.md` first. Grep only identified target files, not whole `src/`. Read specific line ranges, not whole files (unless <150 lines).

## Business Logic Patterns

See skill `.agents/skills/warehousezero-patterns/SKILL.md` for the full reference. Key highlights:

- **Pricing tiers:** Retail (selling_price), Reseller, Distributor — applied per product and per bundle.
- **Bundles:** 16-column spreadsheet import format; recipe = list of `{productId, sku, productName, qty, unit}`.
- **Branch inventory approval flow:** Cabang requests → Pusat approves/rejects in batch.
- **StockOut dual-mode:** Preset bundles (fixed recipe) vs Custom (pick components, editable price).
- **`effectiveOutboundProducts`:** For STAFF_BRANCH, only map approved `branchInventories` for their branchId; for ADMIN, use all `products`.
- **PDF exports:** Format `YYYY-MM-DD_[nomor_dokumen].pdf`, watermark `Dicetak pada: DD MMMM YYYY, HH:mm WIB`.
- **Legacy admin migration:** Auto-migrates `admin@perusahaan.com` from old doc ID to Firebase UID on login.
